Un agent opérationnel qui transforme une intention en actions, tout en laissant le contrôle final à l'humain.

Le principe

De l'intention à l'audit, avec un humain au milieu

Claude choisit lui-même les Tools à partir de leur description. Aucun routage par mots-clés. Mais aucun effet de bord ne part sans une validation explicite.

  1. DemandeUne intention en langage naturel.
  2. AgentClaude sélectionne les Tools adaptés.
  3. PropositionsChaque effet de bord devient une action pending.
  4. Validation humaineApprouver ou refuser, action par action.
  5. ExécutionLe backend vérifie l'accès puis lance le Tool.
  6. AuditTrace, résultats, erreurs, tokens, latence, coût.
Cycle de vie d'une action

Une action en attente n'est jamais présentée comme faite

Après approbation, le backend passe l'action de pending à executing de façon atomique : deux clics simultanés ne peuvent pas lancer deux fois le même Tool.

Si le Tool échoue, l'erreur est remontée telle quelle. Pas de faux succès, pas de résultat inventé.

Un périmètre court et explicite

Les Tools actifs pour l'appel courant sont le périmètre réel de l'agent. Un Tool désactivé n'est jamais remplacé par un autre pour contourner son absence.

create_issueSIDE_EFFECT

Crée une tâche dans l'issue tracker simulé (PostgreSQL).

send_messageSIDE_EFFECT

Simule un message Markdown dans outbox/{channel}.

write_recordSIDE_EFFECT

Enregistre une fiche métier structurée.

generate_documentSIDE_EFFECT

Génère un document Markdown dans files/.

create_calendar_eventSIDE_EFFECT

Pose un événement dans le calendrier interactif.

list_pending_actionsREAD_ONLY

Liste jusqu'à 50 actions en attente d'un plan, exécuté immédiatement.

undo_last_actionSIDE_EFFECT

Annule une action déjà exécutée et réversible.
